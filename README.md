# SmartphoneProgramming_TermProject

프로젝트 제목 : Tundra Survivors

게임 컨셉 : 다가오는 몬스터들을 피하면서 공격하여 성장하는 탑뷰 슈터(뱀서라이크)
원작과의 차이점 : 화염속성 공격을 기본으로 하며, 이 무기의 각 항목을 업그레이드 하여 강해집니다.

개발 범위 : 
플레이어 캐릭터 1종과 액티브 2종(투사체, 주변 범위공격), 패시브 6종(최대 체력증가, 생명력 흡수, 이동속도 증가, 투사체 속도, 투사체 숫자, 공격범위)
적 몬스터 4종(기본 추적, 시간제 돌진, 원거리 공격, 보스)
체력회복 아이템

개발 일정 : 
1주차 04/06~04/12 : 리소스 준비

2주차 04/13~04/19 : 플레이 씬에서 플레이어 이동/애니메이션

3주차 04/20~04/26 : 기본추적 몬스터 구현(생성, 추적,충돌) 

4주차 04/27~05/03 : 돌진,원거리 공격 몬스터 구현

5주차 05/04~05/10 : 몬스터 피격/사망처리 및 경험치획득, 레벨업 시스템(pause 및 선택지)

6주차 05/11~05/17 : UI, 게임 상태 관리

7주차 05/18~05/24 : 배경, 사운드 적용

8주차 05/25~05/31 : 보스 구현 및 마무리

실제 진행
- 개발 진척도
  - 리소스 준비 : 100%
  - 플레이 씬에서 플레이어 이동/애니메이션 : 90% ( 좌,우 이동 부자연스러움 )
  - 기본추적 몬스터 구현(생성, 추적, 충돌) : 100%
  - 돌진, 원거리 공격 몬스터 구현 : 0%
  - 몬스터 피격/사망 처리 및 경험치 획득, 레벨업 시스템 : 90% (레벨업선택지가 아닌 기본 pause 미구현)
  - UI, 게임 상태 관리 : 50% HP,Score,Time,Exp
  - 배경, 사운드 적용 : 20% (오류 발생, 사운드 미적용)
  - 보스 구현 및 마무리 : 30% (보스 미구현, 게임오버 화면 미구현)

  - 시간부족
   - 무기 단일 종류로 변경 -> 레벨업 옵션 다변화
   - 보스 및 몬스터 돌진, 원거리 미구현

- 구체적 나열
  - 사용한 기술 : 객체지향 설계 기반의 컴포넌트 시스템: 모든 게임 오브젝트(Enemy, Fireball, Player)를 IGameObject 인터페이스와 Sprite 클래스를 상속받아 독립적인 update()와 draw()를 수행하도록 설계했습니다.
                 AABB 박스 충돌 판정 알고리즘: Math.abs(ball.x - enemy.x) < radiusSum과 같은 절대값 연산을 사용하여 사각형 범위 기반의 실시간 충돌을 구현했습니다.
                 프레임 기반 애니메이션 시퀀싱: SheetSprite 클래스를 활용하여 텍스처 시트의 좌표를 Rect로 분할하고, 프레임 카운트를 기반으로 이미지를 번갈아 출력하여 골렘과 슬라임의 걷기 애니메이션을 구현했습니다.
                 상태 제어(State Control) 및 타임라인 로직: totalFrames 누적 변수를 활용하여, 시간의 흐름에 따라 적의 스폰 주기(currentSpawnInterval)가 점진적으로 짧아지도록 난이도 곡선(Difficulty Curve)을 코드화했습니다.
- 참고한 것들 : 게임 엔진 구조: 교수님께서 제공한 a2dg 프레임워크의 World 레이어 관리 기법을 참고하여, 총알(PROJECTILE)이 몬스터(PLAYER)보다 앞서 그려지도록 Z-index 레이어링을 적용했습니다.
- 수업 내용에서 차용한 것 : 조이스틱 과제를 했던 경험을 살려 프로젝트에 활용하였습니다.

- 아쉬운 것들
 - 하고싶었지만 못한것들 : 보스구현 및 무기다변화로 인한 만렙 시 무기 간의 조합이 제일 아쉽다.
                         또한 이동로직을 시간을 적용하지 못해 기기마다 차이가 나도록 한 것이 아쉽다.
 - 팔기위해서 보충할 것들 : 해상도 매칭. 캐릭터 및 몬스터 다양화
 - 결국 해결하지 못한 버그 : 오디오버그로 인해 사운드가 적용되지 못했다. 배경음의 경우 잘 고치고 적용하였는데, 효과음을 추가하면서 다같이 버그가 나게 되었다.
                             또한 타이틀 화면의 이미지의 해상도를 맞추지 못했던 기본적인 버그를 해결하지 못해 아쉽다.
                          
 - 기말 프로젝트를 진행하며 겪은 어려움 : 시간이 가장 부족했고, 진행하며 어려웠던 점은 첫 시작과 레벨업시스템이다.

  - 기대한 것 : 코틀린 지식 및 안드로이드 스튜디오 사용법, 여러 예제를 통한 스마트폰 게임 개발에 대한 이해
  - 얻은 것 : 게임 엔진의 메커니즘에 대한 이해
  - 얻지 못한 것 : 코틀린에 대한 개념 정립
  - 더 좋은 수업이 되기 위해 변화할 점 : 자료구조 및 최적화를 위한 로그라이트 장르예제는 어떻습니까!
